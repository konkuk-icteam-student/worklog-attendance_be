## 1. 공통 이름 규칙

| 규칙 | 예 | 나쁜 예 |
|---|---|---|
| 소문자 snake_case | `work_schedule` | `WorkSchedule`, `workSchedule` |
| 영어 단어 사용, 한글·로마자 표기 금지 | `work_attendance` | `chulgeun_record` |
| 테이블 이름은 단수형 | `notification` | `notifications` |
| SQL 예약어 금지 | `member`, `work_date` | `user`, `date`, `order` |
| 따옴표로 감싸야 하는 이름 금지 | `member` | `"user"` |
| 길이 63자 이하 (PostgreSQL 식별자 한도, 넘으면 잘림) | | |
| 약어는 허용 목록만 사용 | `max_concurrent_workers` | `max_conc_wrkr` |

허용 약어: `id`, `url`, `ip`, `pdf`, `min`, `max`. 그 외에는 풀어서 쓴다.

## 2. 테이블

### 2.1 이름

형식은 `{도메인}_{대상}`. 같은 도메인의 테이블은 같은 접두어로 묶는다.

| 도메인 | 접두어 | 예 |
|---|---|---|
| 근무 | `work_` | `work_schedule`, `work_attendance`, `work_change_request` |
| 업무 | `todo` | `todo`, `todo_completion` |
| 알림 | `notification` | `notification`, `notification_check_state` |
| 계정·조직 | 없음 | `organization`, `member`, `member_profile` |

- 상세(자식) 테이블: 부모 이름 + 대상. 예: `work_change_request` → `work_change_request_item`
- 이력 테이블: 대상 이름 + `_history`. 예: `work_schedule_history`
- N:M 매핑 테이블: 두 테이블 이름을 `_`로 연결하고, 주가 되는 쪽을 앞에 둔다. 예: `manager_category`

### 2.2 모든 테이블에 필요한 것

- PK 1개
- 한글 설명 `COMMENT ON TABLE`
- 감사 컬럼 (5장)

## 3. 키 (PK · FK)

### 3.1 PK

| 규칙 | 내용 |
|---|---|
| 컬럼 이름 | `{테이블 이름}_id`. 예: `work_schedule.work_schedule_id` |
| 타입 | `bigint GENERATED BY DEFAULT AS IDENTITY` |
| 복합 PK | 사용하지 않음. 대신 대리키 PK + UNIQUE 조합 |
| 1:1 확장 테이블 | 부모 PK를 그대로 PK 겸 FK로 사용. 예: `member_profile.member_id` |

- `id`만 쓰지 않고 `{테이블}_id`로 쓰는 이유: FK 이름과 같아져서 조인 조건(`ws.work_schedule_id = wa.work_schedule_id`)이 바로 읽힌다.
- `BY DEFAULT`인 이유: 데이터 이관할 때 기존 ID를 그대로 넣을 수 있어야 한다. 이관 후에는 시퀀스 값을 맞춘다(`setval`).

### 3.2 FK

| 경우 | 컬럼 이름 | 예 |
|---|---|---|
| 일반 참조 | 참조하는 PK 이름 그대로 | `work_schedule.member_id` → `member.member_id` |
| 행위자 참조 (누가 했는지) | `{동사 과거형}_by` | `created_by`, `processed_by`, `changed_by` → `member.member_id` |
| 같은 테이블을 두 번 참조 | `{역할}_{PK 이름}` | `from_work_schedule_setting_id`, `to_work_schedule_setting_id` |

- ID 값을 저장하는 컬럼에는 반드시 FK를 건다. "FK 없이 ID만 저장"은 금지한다.
- 예외: 대상이 지워져도 남아야 하는 이력 테이블의 참조 컬럼(예: `work_schedule_history.work_schedule_id`). 이 경우 컬럼 COMMENT에 "FK 없음: 사유"를 적는다.
- FK 컬럼에는 인덱스를 만든다. PostgreSQL은 FK에 인덱스를 자동으로 만들지 않는다.

삭제 동작:

- 기본은 `ON DELETE` 생략(= NO ACTION). 참조되는 행은 지울 수 없다.
- `ON DELETE CASCADE`는 부모 없이는 의미가 없는 소유 관계에만 쓴다. 예: `work_change_request_item` → `work_change_request`, `member_profile` → `member`
- 사용자·조직처럼 여러 곳에서 참조되는 행에는 CASCADE를 쓰지 않는다.

## 4. 컬럼

### 4.1 이름 접미사

| 의미 | 형식 | 타입 | 예 |
|---|---|---|---|
| 시점 (언제 일어났나) | `{동사 과거형}_at` | timestamptz | `created_at`, `processed_at`, `check_in_at` |
| 날짜 | `{대상}_date` | date | `work_date`, `completion_date` |
| 시각 (하루 안의 시간) | `{대상}_time` | time | `start_time`, `end_time` |
| 행위자 | `{동사 과거형}_by` | bigint FK | `created_by`, `corrected_by` |
| 참/거짓 | `is_{형용사}`, `has_{명사}` | boolean | `is_active`, `is_verified`, `is_apply_enabled` |
| 상태·유형 (Enum) | `status`, `type`, `role`, `{대상}_type` | varchar + CHECK | `status`, `change_type` |
| 분 단위 시간 | `{대상}_minutes` | integer | `min_work_unit_minutes` |
| 개수 | `{대상}_count` | integer | `attempt_count` |
| 단위가 있는 값 | `{대상}_{단위}` | integer / numeric | `allowed_radius_m` |

- 같은 의미에는 같은 이름을 쓴다. 시작·종료는 항상 `start_` / `end_`이다(begin, finish 금지). 최소·최대는 `min_` / `max_`를 앞에 붙인다.
- 컬럼 이름에 테이블 이름을 반복하지 않는다. 예: `todo.description` (O) / `todo.todo_description` (X). 단, PK와 FK는 3장 규칙을 따른다.

### 4.2 NULL

- 기본은 NOT NULL. NULL을 허용하려면 "NULL이 무슨 뜻인지"를 컬럼 COMMENT에 적는다.
  - 예: `work_attendance.check_out_at` — "NULL: 아직 퇴근 기록 없음"
  - 예: `work_unavailable_time.start_time` — "NULL: 하루 종일 불가"
- boolean은 항상 `NOT NULL DEFAULT …`. true/false/NULL 세 가지 상태가 필요하면 boolean 대신 Enum을 쓴다.

## 5. 감사 컬럼

| 테이블 성격 | 넣을 컬럼 | 예 |
|---|---|---|
| 사용자가 만들고 고치는 테이블 | `created_at`, `created_by`, `updated_at`, `updated_by` | `work_schedule`, `work_schedule_setting`, `todo` |
| 한 번 쓰고 고치지 않는 기록 | `created_at` (+ 필요하면 `created_by`) | `notification`, `work_schedule_history`, `todo_completion` |
| 회원가입처럼 로그인 전에 생기는 행 | `created_at`, `updated_at` (`*_by` 생략) | `member`, `email_verification_code`, `notification_check_state` |

- `_by`는 항상 `bigint` FK → `member.member_id`.
- `updated_at`은 INSERT 때 `created_at`과 같은 값으로 채운다 (NOT NULL).

삭제:

- 기본은 실제 DELETE. 삭제 기록이 필요하면 이력 테이블에 남긴다.
- 화면에서 "삭제된 항목"을 보여주거나 참조를 보존해야 하면 soft delete로 `deleted_at timestamptz NULL`을 쓴다. `deleted_flag` 같은 boolean은 같이 두지 않는다.

## 6. 데이터 타입

| 용도 | 타입 | 비고 |
|---|---|---|
| PK, FK | bigint | integer, varchar ID 금지 |
| 시점 | timestamptz | 6.1 참고 |
| 근무 날짜·시각 | date, time | 6.1 참고 |
| 짧은 문자열 | varchar(n) | 길이는 아래 표 |
| 긴 글 (사유, 본문) | text | |
| Enum | varchar(30) + CHECK | 7장 |
| 참/거짓 | boolean | |
| 정수 (분, 개수, 학년) | integer | |
| 좌표 | numeric(10,7) | |
| 해시 | varchar(64) (SHA-256 hex) / varchar(255) (bcrypt 등) | |

자주 쓰는 varchar 길이:

| 대상 | 길이 |
|---|---|
| 이름 (사람, 기관) | 50 |
| 이메일 | 100 |
| 전화번호, 학번 | 30 |
| 제목, 학과, 근무지명 | 100 |
| 짧은 설명·사유 (한 줄) | 255 |
| URL, 파일 경로 | text |

### 6.1 시간 타입

- "언제 일어났나"(시점)는 `timestamptz`: 생성·처리·출근 시각 등. 서버나 JVM의 시간대 설정이 바뀌어도 값이 틀어지지 않는다.
- "몇 시에 근무하나"(벽시계 시간)는 `date` + `time`: 근무 일정, 불가 시간, Todo 시각. 근무 일정은 "한국 시간으로 10시"라는 의미라서 시간대를 붙이지 않는다.
- 애플리케이션 시간대는 `Asia/Seoul`로 명시적으로 고정한다.

## 7. Enum

- 코드 테이블(`code`, `code_major`, `code_sub`)은 쓰지 않는다. 값 목록은 Java enum + DB CHECK로 관리한다.
- 값은 대문자 SNAKE_CASE 영어 이름으로, Java enum 상수 이름과 같다. 예: `PENDING`, `WORK_CHANGE_APPROVED`
- 엔티티는 항상 `@Enumerated(EnumType.STRING)`을 쓴다. `ORDINAL`은 금지.
- CHECK는 그 컬럼에 들어갈 값만 허용한다.

```sql
ALTER TABLE work_change_request
  ADD CONSTRAINT ck_work_change_request_status
  CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED'));
```

값을 추가할 때: Java enum과 Flyway 마이그레이션(CHECK 삭제 후 재생성)을 같은 PR에 넣는다.

```sql
-- V7__add_notification_type_reminder.sql
ALTER TABLE notification DROP CONSTRAINT ck_notification_type;
ALTER TABLE notification ADD CONSTRAINT ck_notification_type
  CHECK (type IN ('WORK_CHANGE_APPROVED', 'WORK_CHANGE_REJECTED', 'WORK_SCHEDULE_OPEN', 'REMINDER'));
```

- 값 이름을 바꾸거나 지울 때: 기존 행의 값을 UPDATE한 뒤 CHECK를 바꾼다. 같은 마이그레이션 파일에 넣는다.
- PostgreSQL `CREATE TYPE … AS ENUM`은 쓰지 않는다. 값 삭제·이름 변경이 번거롭고 JPA 매핑도 추가로 필요하다.

## 8. 제약·인덱스 이름과 COMMENT

### 8.1 이름 규칙

| 종류 | 형식 | 예 |
|---|---|---|
| PK | `pk_{테이블}` | `pk_work_schedule` |
| FK | `fk_{테이블}_{컬럼}` | `fk_work_schedule_member_id` |
| UNIQUE | `uk_{테이블}_{컬럼1}_{컬럼2}` | `uk_work_schedule_setting_organization_id_year_month` |
| CHECK | `ck_{테이블}_{컬럼 또는 규칙}` | `ck_work_schedule_time_range` |
| 인덱스 | `idx_{테이블}_{컬럼1}_{컬럼2}` | `idx_work_schedule_member_id_work_date` |
| EXCLUDE | `ex_{테이블}_{규칙}` | `ex_work_schedule_no_overlap` |

- 63자를 넘으면 컬럼 부분을 줄이고, 줄인 이름은 PR에 적는다. 예: `uk_work_schedule_setting_org_year_month`
- 이름을 지정하지 않으면 `fkhvhv118cg23jpqpsu6btexqlc` 같은 이름이 생겨 에러 메시지만 보고 원인을 알 수 없다. 모든 제약에 이름을 지정한다.

### 8.2 인덱스를 만드는 기준

- 기본으로 두는 것은 PK, UNIQUE, 그리고 FK 컬럼 인덱스(3.2)다.
- 성능용 인덱스는 V1에 미리 만들지 않는다. 느린 쿼리가 확인되면 그때 추가한다.

### 8.3 COMMENT

모든 테이블과 컬럼에 한글 설명을 단다. ERD Cloud의 논리명과 같은 내용이다.

```sql
COMMENT ON TABLE work_schedule IS '근무 일정: 학생별 확정 근무, 연속 근무 1구간 = 1행';
COMMENT ON COLUMN work_schedule.work_date IS '근무 날짜';
COMMENT ON COLUMN work_attendance.check_out_at IS '퇴근 시각. NULL: 아직 퇴근 기록 없음';
```
